# 문서 분석 시스템 요구사항 정의서

## 1. 프로젝트 개요

- **프로젝트명:** AI Agent 기반 회의록, 업무보고, 공문자료 등을 이용한 문서 분석 시스템
- **목적:** 회의록, 업무보고, 공문 등 업무 문서를 업로드하면 AI가 핵심 내용을 요약·분석하고 검증 결과를 제공한다.
- **주요 사용자:** 문서의 핵심 내용과 누락·오류 여부를 빠르게 확인해야 하는 업무 담당자
- **사용 상황:** 보고서, 회의자료, 기획서, 정책 문서, 업무 문서의 핵심 내용을 검토할 때 사용한다.
- **핵심 가치:** 문서 검토 시간을 단축하고, 요약 품질을 표준화하며, 최종 검토를 보조한다.
- **MVP 범위:** 로그인, 데이터베이스, 고급 UI 없이 단일 문서를 분석하고 결과를 확인하는 흐름을 우선 구현한다.

## 2. 기술 및 처리 대상

- 언어·백엔드: Python 3, FastAPI
- AI 워크플로: LangChain, LangGraph, LLM API
- 지원 문서: PDF, DOCX, TXT, HWPX, PPTX
- HWPX 처리: `python-hwpx` 사용. HWP(v5 바이너리) 파일은 지원하지 않으며 HWPX 변환이 필요하다.
- OCR: 텍스트를 추출할 수 없는 스캔 문서는 후순위 기능으로 둔다. 도입 시 OCR-Python의 적용 가능성을 검토한다.

## 3. 사용자 흐름

1. 사용자가 지원 형식의 문서를 업로드한다.
2. 시스템이 파일 형식·크기·손상 여부를 검증한다.
3. Document Loader가 일반 텍스트 추출을 먼저 시도한다.
4. 텍스트 추출에 성공하면 결과를 Chunking Agent에 전달한다.
5. 텍스트 추출에 실패했거나 스캔본으로 판단되면 PDF 페이지를 이미지로 변환하고 PaddleOCR(한국어)를 실행한다.
6. OCR로 추출한 텍스트를 Chunking Agent에 전달한다.
7. Summary Agent와 Analysis Agent가 요약 및 핵심 분석 결과를 생성한다.
8. Validation Agent가 결과의 근거, 누락 가능성 또는 검토 필요 항목을 표시한다.
9. 사용자가 결과를 확인하고 필요 시 질문을 입력한다.
10. Q&A Agent가 업로드된 문서 범위 안에서 답변한다.

## 4. 기능 요구사항

| ID | 기능 | 입력 | 처리 및 출력 | 우선순위 |
| --- | --- | --- | --- | --- |
| FR-01 | 문서 업로드 | PDF, DOCX, TXT, HWPX, PPTX 파일 | 파일 유효성을 확인하고 분석 작업을 시작한다. | 필수 |
| FR-02 | 텍스트 추출 | 업로드된 문서 | 형식별 로더로 텍스트와 문서명을 추출한다. | 필수 |
| FR-03 | OCR 대체 처리 | 텍스트 추출 실패 또는 스캔 PDF | 페이지 이미지를 생성하고 PaddleOCR(한국어)로 텍스트를 추출한다. | 필수 |
| FR-04 | 청킹 | 일반 추출 또는 OCR 텍스트 | 문맥이 유지되는 단위로 분할하여 AI 분석에 전달한다. | 필수 |
| FR-05 | 핵심 요약 | 분할된 문서 내용 | 핵심 내용, 주요 항목, 결론을 한국어로 제공한다. | 필수 |
| FR-06 | 내용 분석 | 분할된 문서 내용 | 주요 업무, 일정, 담당자, 요청·결정 사항 등 문서에 존재하는 정보를 구조화해 표시한다. | 필수 |
| FR-07 | 검증 결과 | 요약·분석 결과 | 근거가 부족하거나 누락 가능성이 있는 항목을 검토 필요로 표시한다. | 필수 |
| FR-08 | 문서 질의응답 | 사용자의 질문 | 문서에 포함된 정보만 근거로 답변하며, 근거가 없으면 알린다. | 선택 |

## 5. 입력값 및 예외 처리

- 파일을 선택하지 않았거나 지원하지 않는 확장자인 경우 허용 형식을 안내한다.
- 빈 파일, 손상 파일, 텍스트 추출 실패 시 분석을 진행하지 않고 재업로드 방법을 안내한다.
- 파일 크기 제한과 허용 확장자는 환경 설정값으로 관리한다.
- LLM API 연결 실패·시간 초과 시 민감정보 없이 재시도 가능한 오류 메시지를 표시한다.
- HWPX 원본은 수정하지 않으며, 문서 생성 기능이 추가될 경우 결과는 별도 경로에 저장한다.

## 6. 비기능 및 보안 요구사항

- 분석 진행 상태와 실패 원인을 사용자가 알 수 있어야 한다.
- API 키와 토큰은 `.env`로 관리하며 코드·로그·저장소에 노출하지 않는다.
- 개인정보·기밀 문서와 운영 문서는 저장소 및 테스트 픽스처에 커밋하지 않는다.
- 테스트에는 비민감 샘플 문서를 사용하며, 정상 처리·지원하지 않는 형식·빈 파일·추출 실패를 확인한다.

## 7. 완료 기준

- 지원 문서 1개를 업로드하여 요약, 분석, 검증 결과를 확인할 수 있다.
- 잘못된 파일과 처리 실패 상황에서 사용자 안내 메시지가 표시된다.
- HWPX 테스트 문서는 `python-hwpx` 검증을 통과하며 원본 파일이 변경되지 않는다.
- 실행 방법, 환경 변수 이름, 테스트 절차를 README에 기록한다.
