# AI 문서 분석 시스템 요구사항 정의서

## 1. 문서 정보

| 항목 | 내용 |
| --- | --- |

| 문서 목적 | MVP 구현 범위와 검증 기준을 명확히 정의한다. |
| 대상 독자 | 프로젝트 팀원, 평가자, 향후 사용자 |

## 2. 문제 정의

### 2.1 해결하려는 문제

회의록, 업무보고, 공문자료는 내용이 길고 형식이 제각각이라 사용자가 핵심 내용, 결정사항, 담당자, 기한을 빠르게 파악하기 어렵다. 또한 날짜·숫자·담당자·기한 등의 누락 또는 문서 안의 상충 내용을 사람이 직접 찾아야 한다.

### 2.2 서비스 목적

사용자가 문서를 업로드하면 시스템은 텍스트를 추출하고 AI로 핵심 내용을 요약한다. 사용자는 구조화된 결과에서 주요 정보와 확인이 필요한 항목을 빠르게 검토한다.

### 2.3 MVP 성공 기준

지원 문서를 업로드했을 때 다음 흐름이 정상 동작하면 MVP의 핵심 가치를 충족한 것으로 본다.

```text
문서 업로드 → 텍스트 추출 → AI 분석 → 요약·핵심 정보·검증 결과 반환
```

## 3. 사용자와 사용자 문제

| 사용자 | 해결하려는 문제 | 얻어야 하는 결과 |
| --- | --- | --- |
| 일반 직원 | 긴 문서에서 해야 할 일을 찾기 어렵다. | 요약, 업무 항목, 담당자, 기한 |
| 팀장·관리자 | 결정사항과 누락·상충 가능성을 빠르게 검토하기 어렵다. | 결정사항, 검증 결과, 원문 근거 |
| 행정 담당자 | 공문자료의 핵심 지시와 주의사항을 놓칠 수 있다. | 핵심 내용, 일정, 주의사항 |

## 4. MVP 범위

### 4.1 반드시 포함할 기능

| 우선순위 | 기능 | 사용자 가치 |
| --- | --- | --- |
| P0 | 문서 파일 업로드와 형식 검증 | 분석할 문서를 안전하게 제출한다. |
| P0 | 문서 텍스트 추출 | 파일 형식과 관계없이 분석 가능한 텍스트를 얻는다. |
| P0 | AI 핵심 요약 | 긴 문서의 핵심을 빠르게 이해한다. |
| P0 | 주요 정보 추출 | 결정사항, 업무 항목, 담당자, 기한을 확인한다. |
| P0 | 검증 결과 제공 | 누락·상충 가능성을 확인한다. |
| P0 | 구조화된 API 응답과 오류 응답 | 클라이언트가 결과와 실패 원인을 일관되게 처리한다. |

### 4.2 MVP에서 제외할 기능

- 회원가입, 로그인, 권한 관리
- 사용자별 문서 영구 보관·검색·이력 관리
- 관리자 페이지
- 원본 문서 편집·변환
- 여러 문서의 비교·통합 분석
- 이미지·스캔 PDF OCR
- HWP(v5 바이너리) 직접 처리
- 웹 프론트엔드 확정 구현
- AI 결과를 법적·행정적 최종 판단으로 사용하는 기능

## 5. 사용자 흐름

1. 사용자는 지원 형식의 문서 한 개를 업로드한다.
2. 시스템은 파일 형식, 크기, 읽기 가능 여부를 확인한다.
3. 시스템은 문서에서 텍스트와 가능한 원문 위치 정보를 추출한다.
4. 시스템은 AI 분석을 실행한다.
5. 시스템은 요약, 주요 정보, 검증 결과, 경고를 구조화해 반환한다.
6. 사용자는 결과와 원문 근거를 확인하여 최종 판단한다.

## 6. 기능 요구사항

### FR-01. 문서 업로드 및 입력 검증

- 사용자는 한 번에 문서 파일 한 개를 업로드할 수 있어야 한다.
- 시스템은 파일명, 확장자, MIME 타입, 파일 크기를 검증해야 한다.
- 지원 형식은 PDF, DOCX, TXT, HWPX, PPTX이다.
- 지원하지 않는 HWP(v5) 파일에는 HWPX 변환이 필요하다는 안내를 반환해야 한다.
- 원본 파일은 분석을 위한 임시 파일로만 사용하고, 분석 종료 후 삭제해야 한다.

### FR-02. 텍스트 추출

- 시스템은 파일 형식에 맞는 처리기로 텍스트를 추출해야 한다.
- 텍스트를 추출할 수 없거나 내용이 비어 있으면 분석하지 않고 오류를 반환해야 한다.
- 페이지, 슬라이드, 문단 등 원문 위치 정보는 제공 가능한 형식에서 보존해야 한다.
- HWPX 처리에는 `python-hwpx`를 사용해야 한다.

### FR-03. 핵심 요약

- 시스템은 원문을 근거로 전체 요약을 생성해야 한다.
- 요약에는 원문에 없는 사실을 추가하지 않아야 한다.
- 문서 유형에 따라 회의록, 업무보고, 공문자료에 적합한 핵심 항목을 우선 제시해야 한다.
- 분석 근거가 부족하거나 불확실하면 그 사실을 결과에 표시해야 한다.

### FR-04. 주요 정보 추출

시스템은 문서에 존재하는 경우 아래 정보를 추출해야 한다.

- 문서 유형, 제목, 작성일
- 핵심 주제와 키워드
- 주요 결정사항
- 업무 항목과 후속 조치
- 담당자
- 기한과 일정
- 중요 이슈와 주의사항

문서에 없는 정보는 추정하지 않고 `null`, 빈 배열 또는 `확인되지 않음`으로 반환해야 한다.

### FR-05. 문서 검증

- 시스템은 날짜, 숫자, 담당자, 기한, 핵심 항목의 누락 또는 상충 가능성을 식별해야 한다.
- 검증 결과 상태는 `정상`, `주의`, `확인 필요`로 구분해야 한다.
- 각 결과에는 검증 대상, 판단 사유, 원문 근거 또는 위치 정보를 포함해야 한다.
- 검증 결과는 참고용이며 사용자의 최종 확인이 필요하다는 안내를 포함해야 한다.

### FR-06. 분석 결과 반환

성공 응답에는 최소한 아래 정보를 포함해야 한다.

```json
{
  "status": "success",
  "document": {
    "filename": "example.docx",
    "file_type": "docx"
  },
  "summary": "문서의 핵심 요약",
  "key_points": [],
  "action_items": [],
  "validation": {
    "status": "normal",
    "items": []
  },
  "warnings": []
}
```

- 실패 응답에는 오류 코드, 사용자용 오류 메시지, 가능한 조치를 포함해야 한다.
- 응답과 로그에는 API 키, 인증정보, 개인정보, 불필요한 원문 내용을 포함하지 않아야 한다.

### FR-07. 오류 처리

시스템은 다음 오류를 구분해야 한다.

- 지원하지 않는 파일 형식
- 파일 크기 제한 초과
- 파일 손상 또는 읽기 실패
- 텍스트 추출 실패
- 빈 문서
- AI 분석 시간 초과 또는 서비스 오류
- AI 결과 형식 검증 실패

내부 예외 상세는 노출하지 않고 사용자가 취할 수 있는 조치를 안내해야 한다.

## 7. 비기능 요구사항과 제약사항

### 7.1 기술 제약

- Python 3.10 이상을 사용한다.
- 백엔드는 FastAPI를 사용한다.
- AI 워크플로는 LangChain과 LangGraph를 사용한다.
- 초기 MVP는 데이터베이스를 사용하지 않는다.
- 프론트엔드 구현 여부와 기술은 MVP 이후에 결정한다.

### 7.2 보안과 개인정보

- API Key, 비밀번호, 토큰은 코드와 문서에 직접 작성하지 않는다.
- 비밀값은 환경변수로 관리하고 `.env` 파일은 커밋하지 않는다.
- 업로드 파일과 원문 내용은 영구 보관하지 않고, 처리 후 임시 파일을 삭제한다.
- 개인정보와 문서 원문을 로그에 기록하지 않는다.
- 외부 AI API를 사용하면 문서 전송 사실과 보안상 주의사항을 사용자에게 안내한다.

### 7.3 품질과 안정성

- 정상 입력과 주요 오류 입력에 대해 일관된 상태와 메시지를 반환해야 한다.
- AI 결과는 응답 전에 구조를 검증해야 한다.
- 원본 문서를 덮어쓰지 않아야 한다.
- 스캔 PDF와 이미지 중심 문서는 OCR 미지원 상태에서는 분석 품질이 제한될 수 있음을 안내해야 한다.

## 8. 수용 기준

| ID | 검증 조건 | 기대 결과 |
| --- | --- | --- |
| AC-01 | 지원 형식의 정상 문서를 업로드한다. | 텍스트 추출과 분석 결과가 반환된다. |
| AC-02 | 분석 결과를 확인한다. | 요약, 주요 정보, 업무 항목, 검증 결과가 구조화되어 있다. |
| AC-03 | 지원하지 않는 형식 또는 HWP(v5)를 업로드한다. | 분석하지 않고 형식 오류와 안내를 반환한다. |
| AC-04 | 빈 문서·손상 파일·추출 불가 문서를 업로드한다. | 원인별 오류가 구분되어 반환된다. |
| AC-05 | 문서에 담당자 또는 기한이 없다. | 값을 추정하지 않고 `확인되지 않음` 등으로 표시한다. |
| AC-06 | 누락 또는 상충 가능성이 있는 문서를 분석한다. | 상태, 판단 사유, 원문 근거가 포함된 검증 결과를 반환한다. |
| AC-07 | 분석이 종료된다. | 원본 파일이 영구 저장되지 않고 민감정보가 로그에 노출되지 않는다. |
| AC-08 | HWPX 테스트 문서를 처리한다. | `python-hwpx` 기반 처리와 저장 검증이 가능하다. |

## 9. 테스트 범위

### 정상 입력

- TXT, DOCX, PDF, HWPX, PPTX 샘플 문서
- 담당자·기한·결정사항이 포함된 회의록
- 표와 문단이 섞인 업무보고·공문자료

### 주요 오류 입력

- 지원하지 않는 확장자와 HWP(v5) 파일
- 파일 크기 제한 초과 파일
- 손상 파일과 빈 파일
- 텍스트를 읽을 수 없는 문서
- AI 시간 초과와 형식이 잘못된 AI 응답

각 테스트는 입력, 기대 상태 코드, 응답 필드, 오류 메시지, 임시 파일 삭제 여부를 확인한다. HWPX 저장 기능을 구현하는 경우에는 `MutationReport`와 라이브러리 검증 결과를 함께 확인한다.

## 10. 가정과 보류 사항

### 현재 가정

- MVP는 인증 없이 단일 문서를 분석하는 API를 제공한다.
- 분석 결과는 참고용이며 사용자가 원문을 최종 확인한다.
- 업로드 크기 제한과 목표 처리 시간은 구현 전 팀에서 결정한다.

### 구현 전 결정이 필요한 사항

- 외부 AI 모델·API 사용 여부와 문서 외부 전송 정책
- 최대 파일 크기, 최대 페이지 수, 목표 응답 시간
- 결과를 제공할 클라이언트 형태(API만 제공 또는 웹 화면 포함)
- 문서 유형별 검증 규칙의 상세 목록
