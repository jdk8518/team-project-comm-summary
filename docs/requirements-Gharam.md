# AI 문서 분석 시스템 요구사항 정의서

## 1. 문서 개요

- 문서명: AI Agent를 활용한 문서 분석 시스템 요구사항 정의서
- 작성자: Gharam
- 프로젝트명: AI Agent를 활용한 회의록·업무보고·공문자료 분석 시스템
- 작성일: 2026-07-23
- 문서 목적: 문서를 업로드하면 AI가 핵심 내용을 요약하고 문서 내용의 검증 결과를 제공하는 MVP의 요구사항을 정의한다.

## 2. 프로젝트 개요

### 2.1 서비스 목적

회의록, 업무보고, 공문자료 등 업무 문서를 AI로 분석하여 사용자가 긴 문서를 빠르게 이해하고, 후속 업무와 내용상의 문제를 확인할 수 있도록 한다.

### 2.2 해결하려는 문제

사용자는 문서를 처음부터 읽지 않아도 핵심 내용, 결정사항, 업무 항목을 파악할 수 있어야 한다. 또한 숫자·날짜·담당자·기한 등의 누락이나 문서 내 주요 내용의 불일치를 빠르게 확인할 수 있어야 한다.

### 2.3 대상 사용자

- 일반 직원: 회의록과 업무보고의 핵심 내용 및 할 일을 확인한다.
- 팀장·관리자: 결정사항, 담당자, 기한과 주요 이슈를 검토한다.
- 행정·공공기관 담당자: 공문자료의 핵심 내용과 주의사항을 확인한다.

## 3. 범위

### 3.1 MVP 포함 범위

- 문서 파일 업로드
- PDF, DOCX, TXT, HWPX, PPTX 파일의 텍스트 추출
- 추출 텍스트의 AI 요약
- 주요 정보 추출
- 문서 내용 검증 및 검증 결과 제공
- 성공·실패 상태를 포함한 JSON 기반 API 응답
- 업로드 원본을 영구 저장하지 않는 임시 처리

### 3.2 MVP 제외 범위

- 회원가입, 로그인, 권한 관리
- 사용자별 문서 보관 및 검색
- 관리자 페이지
- 원본 문서 편집 및 변환
- HWP(v5 바이너리) 직접 처리
- 웹 프론트엔드의 확정 구현
- AI 결과의 법적·행정적 최종 판단 대체

## 4. 사용자 시나리오

1. 사용자는 분석할 문서 파일을 선택하여 업로드한다.
2. 시스템은 파일 형식과 크기를 확인한다.
3. 시스템은 문서에서 텍스트를 추출한다.
4. 시스템은 추출한 내용을 AI 분석 워크플로에 전달한다.
5. AI는 요약, 주요 정보, 검증 결과를 생성한다.
6. 시스템은 결과를 구조화된 응답으로 반환한다.
7. 사용자는 결과를 확인하고 원문을 기준으로 최종 판단한다.

## 5. 기능 요구사항

### FR-01. 문서 업로드

- 사용자는 하나의 문서 파일을 업로드할 수 있어야 한다.
- 시스템은 파일명, 확장자, MIME 타입, 파일 크기를 검증해야 한다.
- 지원 확장자는 `.pdf`, `.docx`, `.txt`, `.hwpx`, `.pptx`로 한다.
- 사용자 원본 파일은 분석을 위해 임시로 사용하며, 기본 정책상 분석 완료 후 삭제한다.

### FR-02. 문서 텍스트 추출

- 파일 형식에 맞는 처리기를 사용하여 문서 텍스트를 추출해야 한다.
- 추출 결과가 없거나 읽을 수 없는 문서는 오류로 처리해야 한다.
- HWP(v5)는 지원하지 않으며 HWPX로 변환해야 한다는 안내를 제공해야 한다.
- 페이지·슬라이드·문단 등 원문 위치 정보는 가능한 경우 결과 근거로 보존해야 한다.

### FR-03. AI 요약

- 시스템은 문서의 전체 요약을 생성해야 한다.
- 요약은 원문에 없는 사실을 임의로 추가하지 않아야 한다.
- 문서 유형에 따라 회의록, 업무보고, 공문자료에 적합한 항목을 우선적으로 제시해야 한다.
- 분석 결과가 불확실한 경우 불확실성을 표시해야 한다.

### FR-04. 주요 정보 추출

가능한 경우 다음 정보를 추출해야 한다.

- 문서 유형
- 제목 및 작성일
- 핵심 주제·키워드
- 주요 결정사항
- 업무 항목 및 후속 조치
- 담당자
- 기한·일정
- 중요 이슈 및 주의사항

정보가 문서에 없으면 추정하지 않고 `null`, 빈 배열 또는 “확인되지 않음”으로 표시한다.

### FR-05. 문서 검증

- 시스템은 문서에서 검증 가능한 날짜, 숫자, 담당자, 기한 및 핵심 항목을 식별해야 한다.
- 동일 문서 내에서 서로 충돌하는 내용이나 누락 가능성이 있는 항목을 표시해야 한다.
- 검증 결과는 `정상`, `주의`, `확인 필요` 등 명확한 상태로 구분해야 한다.
- 각 검증 결과에는 검증 대상, 판단 근거, 관련 원문 위치 또는 인용 가능한 문맥을 포함해야 한다.
- AI의 검증 결과는 참고용이며 사용자의 최종 확인이 필요하다는 안내를 제공해야 한다.

### FR-06. 결과 반환

분석 성공 시 시스템은 다음 구조를 포함한 JSON 응답을 반환해야 한다.

```json
{
  "status": "success",
  "document": {
    "filename": "example.docx",
    "file_type": "docx"
  },
  "summary": "문서의 핵심 요약",
  "key_points": [],
  "action_items": [],
  "validation": {
    "status": "normal",
    "items": []
  },
  "warnings": []
}
```

- 실패 시 사용자가 이해할 수 있는 오류 코드와 메시지를 반환해야 한다.
- 개인정보·인증정보·API 키 등 민감정보를 로그나 응답에 불필요하게 포함하지 않아야 한다.

### FR-07. 오류 처리

다음 상황을 구분하여 처리해야 한다.

- 지원하지 않는 파일 형식
- 파일 크기 제한 초과
- 파일 손상 또는 읽기 실패
- 텍스트 추출 실패
- 빈 문서
- AI 분석 서비스 오류 또는 시간 초과
- 결과 형식 검증 실패

오류 발생 시 내부 예외 내용 전체를 노출하지 않고, 원인과 사용자가 취할 수 있는 조치를 안내한다.

## 6. 비기능 요구사항

### NFR-01. 기술 스택

- Python 3.10 이상
- FastAPI 기반 백엔드
- LangChain 및 LangGraph 기반 AI 워크플로
- PDF, DOCX, TXT, HWPX, PPTX 처리 라이브러리 사용
- 초기 단계에서는 데이터베이스를 사용하지 않는다.
- HWPX 처리에는 `python-hwpx`를 사용한다.

### NFR-02. 보안 및 개인정보

- API Key, 비밀번호, 토큰은 소스 코드에 작성하지 않는다.
- 비밀값은 환경변수로 관리하고 `.env`는 커밋하지 않는다.
- 업로드 문서는 영구 저장하지 않으며 임시 파일은 처리 후 삭제한다.
- 원문 내용과 개인정보가 로그에 남지 않도록 한다.
- 외부 AI API로 문서를 전송하는 경우 사용자에게 전송 사실과 보안상 주의사항을 안내한다.

### NFR-03. 안정성

- 정상 입력뿐 아니라 지원하지 않는 형식, 손상 파일, 빈 문서에 대해 일관된 오류 응답을 제공한다.
- AI가 구조화된 결과를 반환하지 못하면 결과 형식을 검증하고 재처리 또는 오류 응답을 수행한다.
- 원본 파일을 덮어쓰지 않는다.

### NFR-04. 사용성

- API 오류 메시지는 비개발자도 이해할 수 있는 표현을 사용한다.
- 요약과 검증 결과를 분리하여 확인할 수 있어야 한다.
- 근거가 없는 정보는 추정 결과로 표시하지 않는다.

## 7. 입력 및 출력 정의

### 입력

- multipart/form-data 방식의 문서 파일
- 파일명과 확장자
- 선택 입력: 분석 문서 유형 또는 사용자 분석 지시사항

### 출력

- 처리 상태
- 파일 기본 정보
- 전체 요약
- 주요 내용 및 키워드
- 결정사항
- 업무 항목, 담당자, 기한
- 검증 상태와 검증 항목
- 경고 및 오류 정보

## 8. 수용 기준

- 지원 대상 파일을 업로드하면 텍스트 추출과 AI 분석 결과가 반환된다.
- 결과에 요약, 주요 정보, 업무 항목, 검증 결과가 구조화되어 포함된다.
- 지원하지 않는 파일은 분석하지 않고 명확한 오류를 반환한다.
- 빈 문서·손상 파일·텍스트 추출 실패를 구분하여 처리한다.
- 원본 파일이 분석 후 영구 보관되지 않는다.
- API Key와 문서 원문이 로그에 노출되지 않는다.
- HWPX 파일은 `python-hwpx` 기반 처리 및 저장 검증이 가능해야 한다.

## 9. 테스트 요구사항

### 정상 입력

- 요약 가능한 TXT, DOCX, PDF 파일
- 표와 문단이 포함된 문서
- 회의록의 담당자·기한·결정사항이 포함된 문서
- HWPX 샘플 문서

### 오류 입력

- 지원하지 않는 확장자
- 파일 크기 제한 초과 파일
- 손상된 파일
- 내용이 없는 파일
- 읽을 수 없는 HWP(v5) 파일
- AI 서비스 시간 초과 또는 잘못된 구조화 응답

각 테스트는 입력, 기대 상태 코드, 응답 필드, 오류 메시지, 임시 파일 삭제 여부를 확인한다. HWPX 테스트는 요청한 내용 변경 여부와 `MutationReport` 및 라이브러리 검증 결과를 함께 확인한다.

## 10. 제약사항 및 위험요소

- 문서 형식과 내부 구조에 따라 텍스트 추출 품질이 달라질 수 있다.
- 스캔 PDF나 이미지 기반 문서는 OCR 없이는 분석이 제한될 수 있다.
- AI 요약과 검증 결과는 원문 및 프롬프트 품질에 영향을 받는다.
- 긴 문서는 토큰 제한과 처리 시간 문제를 일으킬 수 있다.
- 외부 AI API 사용 시 문서의 개인정보·기밀성 및 비용을 검토해야 한다.
- 초기 버전은 결과를 참고용으로 제공하며 법률·행정적 판단을 자동화하지 않는다.

## 11. 향후 확장 방향

- 웹 프론트엔드 제공
- 여러 문서 비교 및 통합 분석
- 사용자 인증과 문서 보관
- OCR 기반 이미지 문서 처리
- 결과 다운로드 및 공유
- 평가 데이터셋 기반 요약·추출·검증 정확도 측정
