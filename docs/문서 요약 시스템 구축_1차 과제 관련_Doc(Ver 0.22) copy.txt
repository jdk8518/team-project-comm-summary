## 8. 외부 문서 처리: HWPX

HWPX 읽기, 수정, 생성, 검증 기능은 [`python-hwpx`](https://github.com/airmang/python-hwpx)를 사용해 구현합니다. Python 3.10 이상에서 `pip install python-hwpx`로 설치하고, 의존성은 프로젝트의 `requirements.txt` 또는 `pyproject.toml`과 잠금 파일에 명시합니다. 외부 라이브러리의 소스 코드를 이 저장소에 복사하지 않습니다.

`HwpxDocument.open()`으로 원본을 열고, 결과는 예를 들어 `output/report-updated.hwpx`처럼 새 경로에 저장합니다. 개발·테스트 중 사용자 원본을 덮어쓰지 않습니다. HWP(v5 바이너리)는 HWPX로 변환 후에 문서 추출해야 합니다.

문서 쓰기 후에는 `save_to_path(..., return_report=True)`의 `MutationReport`를 확인하고, 비민감 HWPX 테스트 픽스처로 회귀 테스트를 추가합니다. 테스트는 요청한 내용 변경과 저장 결과의 라이브러리 검증 통과를 모두 확인해야 합니다. 개인정보·기밀·운영 문서는 저장소에 커밋하지 않습니다.

4) 사람의 업무 흐름 정리 Codex Prompt
-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
vibe-frame-kit 기준으로 요구사항 정의를 만들어줘.

AI Agent 기반 회의록, 업무보고, 공문자료 등을 이용한 문서 분석 시스템을 만들기 전에,
사람이 직접 문서를 분석하고 요약하는 업무 흐름을 먼저 정리해줘.

다음 관점으로 작성해줘.
1. 사람이 수행하는 작업 단계
2. 각 단계의 목적은 문서에 대한 제목과 일자, 소속기관(부서)를 기준으로 분석
3. 각 단계에서 확인해야 할 정보
    1) 문서 확인 
        - 분석할 문서의 종류와 목차, 일자, 소속기관(소속부처, 소속부서 등)을 확인
    2) 문서 읽기
        - 문서의 작성 기관(부서), 작성 일자, 제목, 목차, 본문, 결론을 읽음
    3) 핵심 내용 표시
        - 중요한 문장, 키워드, 수치, 조건, 결정사항을 찾음
    4) 내용 분류
        - 배경, 문제, 해결방안, 결론 등으로 정리
    5) 요약 작성
        - 핵심 내용을 일정별, 주요 제목별로 짧고 명확하게 다시 작성
    6) 결과 검토
        - 원문과 요약이 일치하는지 확인
4. 시스템 기능으로 전환할 수 있는 부분
5. 사람이 최종 검토해야 하는 부분

결과는 표와 Mermaid 흐름도로 작성해줘.
이 부분을 직접 requirements-Gharam.md에 추가하지 마.

점검 기준:

작업 방식:
- 새로운 기능을 과도하게 추가하지 마.

-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------

다중 파일 업로드 기능을 추가하라.
목적 : 여러 파일을 동시에 업로드하여 작업할 수 있도록 하고, 시스템이 순차적으로 처리하는 대로 리스트를 실시간 갱신하고, 사용자는 리스트가 만들어지는 대로 확인할수 있도록 하여 효율을 높인다.

1. 파일 업로드 화면에서 여러 파일을 선택할 수 있도록 한다.
2. 폴더도 선택할 수 있도록 한다.
3. 폴더를 선태한 경우에는 폴더 하위의 구조를 모두 탐색하여 업로드한다.
4. 업로드 대상 파일은 반드시 프로젝트에서 지정한 파일 종류로 한정한다.
5. 업로드 대상 파일이나 폴더에 소속된 파일중에 프로젝트에서 지정한 파일 종류가 아닌 경우에는 처리 불가 파일로 지정하여 화면의 맨 하단에 처리 불가 파일 리스트로 제공한다.
6. 처리 불가파일의 표시 항목은 원본저장경로, 파일명, 작성일시, 파일크기 로 한다.

DB 구조 변경
1. DB에 "사용자확인" 항목을 추가한다. 값은 True, False 이다.
2. 파일업로드 화면에 접속하면, 하단에 "사용자확인"값이 False 인 파일들의 리스트를 다중파일 작업리스트로 표시한다.

다중 파일 처리 방식
0. 파일을 1개만 처리하는 경우에는 기존의 요약화면을 보여주고 저장하도록 한다.
1. 다중파일 처리시에는 AI의 요약 분석 검증 결과가 나오는 대로 사용자에게 묻지 않고 파일을 저장, DB에도 입력한다. 이때 "사용자확인"값은 False이다.
