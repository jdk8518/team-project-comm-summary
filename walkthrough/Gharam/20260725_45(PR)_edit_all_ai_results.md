## 수행 내용

AI 분석·요약·검증 결과 전체를 `DocumentResultsUpdate` 스키마로 명시하고 `PUT /api/v1/documents/{file_id}/results`에서 한 번에 저장하도록 구현했다. DB 기록은 분석 결과, 요약 결과, 검증 결과의 전체 필드를 보존하며 저장된 원본이 있는 경우 같은 위치의 Markdown sidecar도 즉시 재생성한다. 기존 파일 저장 요청에도 세 결과 객체를 선택적으로 포함할 수 있도록 확장했다.

업로드 결과 화면과 검색 문서 수정 팝업에 전체 결과 JSON 편집 영역을 추가했다. JSON 내부의 분석, 요약, 검증 모든 항목을 수정할 수 있고, 형식과 필수 최상위 항목을 저장 전에 검증한다. 기존 검색 수정 팝업의 저장 경로 변경과 삭제 버튼은 유지했다.

## 입력과 출력

입력은 분석·요약·검증 결과 객체 전체다. 출력은 DB에 저장된 최신 결과와 모든 결과 항목이 반영된 Markdown sidecar다. 검색 화면의 `수정` 버튼은 동일한 편집 팝업을 열고, `삭제` 버튼은 기존 삭제 API를 호출한다.

## 다른 기능과 연결할 부분

기존 분석 파이프라인의 Pydantic 결과 모델, 파일 저장/이동 시 Markdown 생성, 검색 문서 상세 팝업을 재사용한다.

## 공통 구조에 미치는 영향

결과 저장 스키마와 프론트 편집 UI를 확장했다. 기존 API의 기본 동작과 인메모리 DB 구조는 유지하며, 운영 환경에서는 동일 스키마를 영속 DB 테이블로 이전할 수 있다.

## 남아 있는 문제

현재 편집기는 전체 결과를 JSON 텍스트로 수정하는 방식이다. 운영 UX에서는 항목별 반복 입력 컨트롤과 영속 DB 마이그레이션이 추가로 필요하다. 기존 무관 변경 파일은 보존했다.
