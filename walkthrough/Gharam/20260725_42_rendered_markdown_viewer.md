## 수행 내용

검색 결과 카드의 `MD` 버튼이 새 탭에서 원문을 여는 대신 검색 화면의 Markdown 뷰어 팝업을 열도록 변경했다. `/api/v1/documents/{file_id}/markdown`에서 Markdown을 조회한 뒤 제목, 소제목, 문단, 순서·비순서 목록, 인용문, 굵은 글씨와 inline code를 렌더링한다. HTML 특수문자를 먼저 escape해 저장된 요약 내용이 HTML로 실행되지 않도록 했다.

뷰어에는 로딩·오류 상태와 닫기 버튼을 제공한다. 문서 리스트 초기 화면에서는 기존 상세 요약 패널을 계속 숨기며, MD 버튼을 누른 경우에만 별도 뷰어가 활성화된다.

## 입력과 출력

입력은 검색 문서의 `file_id`다. 출력은 저장된 Markdown sidecar를 렌더링한 팝업 화면이며, 파일이 없거나 API 오류가 발생하면 팝업 안에 오류 메시지를 표시한다.

## 테스트 방법과 결과

`static/index.html`의 JavaScript 문법 검사를 통과했다. `python -m pytest tests -q` 결과는 `21 passed, 2 warnings`이다. Markdown 조회 API의 응답과 저장된 요약 내용은 기존 통합 테스트에서 확인했다. `git diff --check`도 통과했다.

## 다른 기능과 연결할 부분

뷰어는 저장 단계에서 생성된 `.md` sidecar와 Markdown 조회 API를 사용한다. 요약 수정·파일 이동·삭제 시 sidecar를 갱신·이동·삭제하는 기존 흐름과 연결된다.

## 공통 구조에 미치는 영향

프론트엔드 검색 화면에 뷰어 팝업과 렌더러만 추가했으며, 원본 다운로드와 요약 수정 API는 변경하지 않았다.

## 남아 있는 문제

현재 렌더러는 MVP 범위의 기본 Markdown 문법만 지원하며 표, 링크, 코드 블록 등은 일반 텍스트로 표시될 수 있다. 복잡한 Markdown 지원이 필요하면 검증된 Markdown 렌더링 라이브러리 도입을 별도 검토해야 한다. 기존 무관 문서 변경은 보존했다.
