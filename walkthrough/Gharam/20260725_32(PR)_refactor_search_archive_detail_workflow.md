## 작업 지시사항 원문

> vibe-frame-kit의 refactoring-coach 기준을 참조해서
> 현재 MVP 코드를 리팩토링하라.
>
> 1. 파일 검색 화면의 검색 방식 수정
> - 폴더를 선택하는 경우 해당 폴더의 하위계층 전체 리스트가 검색 대상이다.
> - "파일 저장 폴더"를 선택하는 경우 폴더 경로에 따른 검색 조건은 없다.
> - "파일 저장 폴더"는 파일 저장을 위한 루트 폴더이다.
>
> 2. 파일저장 기본 경로의 설정
> - "파일 저장 폴더"는 프로젝트의 루트/output/ 으로 고정한다.
> - 파일업로드 화면에서 파일저장 경로중 /output/는 표시하지 않는다.
>
> 3. 아카이빙 문서 상세 요약 페이지는
> - 파일 리스트에서 선택시 따로 표시되도록 변경하라.
> - 요약 내용을 수정할 수 있으며, 저장시에 저장 경로가 바뀌면 파일을 이동하고, DB를 업데이트한다.
> - 삭제버튼을 표시하고, 삭제시에는 파일과 DB의 자료를 삭제한다.

## 수행 내용

- 파일 저장 루트를 `output`으로 고정하기 위해 저장 경로 정규화 함수를 추가했다.
- 저장 및 이동 API 내부에서 입력 경로가 `output` 하위가 되도록 보정하고, 상위 경로 이탈을 차단하도록 했다.
- 검색 API의 폴더 필터를 정확히 일치에서 선택 폴더와 모든 하위 폴더 포함 방식으로 변경했다.
- `folder=output` 또는 파일 저장 폴더 루트 선택 시 폴더 조건 없이 전체 검색 결과가 나오도록 했다.
- 파일 검색 화면을 폴더 트리, 검색 결과 목록, 상세 요약 패널의 3영역으로 재구성했다.
- 폴더 트리는 파일을 표시하지 않고 폴더만 표시하도록 구성했다.
- 업로드 화면의 저장 경로 입력값은 화면에서 `output/`를 숨기고, 저장 요청 시 `output/`를 다시 붙이도록 했다.
- 검색 결과 파일 선택 시 우측 상세 요약 패널에 별도 표시되도록 하고, 기본 선택은 검색 결과 최상단 파일이 되도록 했다.
- 상세 요약 패널에서 요약 수정, 저장 경로 이동, 원본 다운로드, 삭제가 가능하도록 연결했다.
- 삭제 시 기존 DELETE API를 호출해 파일과 인메모리 DB 자료를 함께 삭제하도록 했다.

## 다른 기능과 연결할 부분

- 상세 요약 패널의 저장 버튼은 `PUT /api/v1/documents/{file_id}/summary`와 `PUT /api/v1/documents/{file_id}/folder`를 순서대로 호출한다.
- 삭제 버튼은 `DELETE /api/v1/documents/{file_id}`와 연결된다.
- 저장 후 검색 화면 이동 흐름은 기존 저장 API 응답을 사용하며, 저장된 파일을 자동 선택 대상으로 유지한다.

## 공통 구조에 미치는 영향

- 공통 저장 루트 상수 `ARCHIVE_ROOT`를 `output`으로 정리했다.
- 저장 경로 정규화 로직이 추가되어, 향후 저장/이동 API는 프로젝트 루트의 `output` 하위 경로를 기준으로 동작한다.
- 기존 API 엔드포인트 구조는 유지했고, 검색 API의 `folder` 파라미터 의미만 하위 폴더 포함으로 확장했다.
