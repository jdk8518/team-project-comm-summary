## 원인 분석

- 파일 검색 결과에서 상세 수정 화면을 열 때 호출하는 `GET /api/v1/documents/{file_id}/result`가, 기존 SQLite 레코드의 `saved_folder` 또는 `saved_filename`이 `None`인 경우 Pydantic 문자열 필드 검증에서 서버 500을 낼 수 있었습니다.
- 브라우저는 서버의 `Internal Server Error` 평문을 `response.json()`으로 해석하려고 해 `Unexpected token 'I'` 오류를 표시했습니다.

## 수행 내용

- 상세 결과 API가 저장 경로·파일명의 `None` 값을 추천값 또는 원본 파일명으로 보완하고, 이전 형식의 분석·요약·검증 데이터도 안전하게 다시 구성하도록 수정했습니다.
- 프런트엔드가 비JSON 오류 응답을 그대로 보여 주도록 JSON 응답 처리 함수를 추가했습니다.
- 요약 자료와 등록 부서 목록을 AI API에 전달하는 소속 부서 추천 API와, API 실패 시 후보 부서 목록을 반환하는 안전한 폴백을 추가했습니다.
- 업로드 화면의 기본값을 `부서 추천`, `경로 추천`으로 변경하고, 직접 입력한 부서·경로는 그대로 사용하도록 연결했습니다.
- 다중 파일 작업 목록의 파일명 열을 3배로 넓히고 저장 경로에서 `output/` 접두사를 숨겼습니다.
- 아카이빙 상세 요약 모달에서 부서·저장 경로를 상단 한 줄 구성으로 옮기고 부서 추천 버튼을 추가했으며, 중복 표시하던 하단 소속 부서·문서 목적·핵심 메시지 텍스트를 제거했습니다.
- 단일 분석 결과 화면에도 상단·하단 저장/삭제 버튼과 상단 보관 정보 편집 영역을 추가했습니다.

## 수동 확인 방법

1. 서버를 정상 Python 환경에서 실행합니다: `python -m uvicorn app.main:app --reload`.
2. 파일검색 탭에서 저장 폴더 `output`, 전체 부서, 빈 검색어로 검색합니다.
3. 목록의 수정 버튼과 Markdown 뷰어의 수정 버튼을 각각 눌러 상세 요약 모달이 열리는지 확인합니다.
4. 상세 모달의 `부서 추천`을 눌러 후보 부서 버튼이 표시되고 선택값이 반영되는지 확인합니다.
5. 업로드 화면에서 `부서 추천`·`경로 추천` 기본값으로 단일 및 다중 파일을 분석하고, 직접 입력한 값도 각각 보관 정보에 반영되는지 확인합니다.
6. 다중 파일 작업 목록에서 파일명 열 너비와 `output/`이 제거된 경로 표시를 확인합니다.
